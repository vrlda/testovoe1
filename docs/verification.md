# Проверка обеих итераций

- Чистая установка через `npm ci`, TypeScript и production-сборка.
- Автоматические проверки: фиксация версии и варианта, публикация и rollback, уникальность событий, изоляция ошибок пачки, валидация, HTTP, TTL и сохранение очереди при сетевых ошибках.
- Генератор на отдельной локальной базе v1: 120 сессий, 60 A / 60 B, по 15 сессий каждого варианта в четырёх кампаниях, 47 результатов и 29 сессий с кликом. 951 принятое событие просмотра/CTA и 280 ответов о дубле.
- Метрики 16 шагов двух вариантов сверены с независимыми SQL-запросами.
- Браузер: прохождение до рекомендации, валидация, Back, refresh, восстановление черновиков и повторное открытие, восстановление после ошибки сети, фильтр кампании, управление распределением и публикацией.
- Интерфейс проверен на ширине 320, 390 и 1440 пикселей. Широкие таблицы прокручиваются внутри страницы. Контент предоставленных JSON отображается на английском.
- Исходный `workstyle-v1.json` сохранён без изменений. Генератор не запускается автоматически и не использовался для заполнения публичной базы.

## Вторая итерация

- Предоставленные `workstyle-v2.json` и `workstyle-v3.json` сохранены без изменений.
- Тест проходит последовательную публикацию v1 → v2 → v3, продолжение ранее открытых сессий v1/v2, условную ветку `security_constraints`, отсутствие `tool_count` в B, новый результат и дедупликацию `recommendation_expanded`.
- Тест выполняет откат v3 → v2 и сверяет аналитику и SQL-схему до и после; сессия v3 остаётся закреплённой за v3.
- Генератор отдельно проверен на активной v3: 120 сессий (60 A / 60 B), 993 принятых события и 283 ответа о дубле, включая `recommendation_expanded`. Публичную базу синтетическими данными не заполняем.
- На публичном стенде выполнены публикации v2 → v3, rollback до v2 и повторная публикация v3. Активна внутренняя версия 4 с исходным JSON v3. Старая сессия осталась закреплённой за v1; число сессий (2), событий (9) и SQL-схема не изменились в ходе публикации и отката.

## Проверка защиты API

Регрессии покрывают обязательный токен, ограничения UTM по байтам (включая Unicode и старые строки базы), размер пачки, лимит событий сессии, дедупликацию на лимите, ограничение частоты запросов, поддельный `X-Forwarded-For` и повтор очереди после `429`.

Локально в браузере проверены: ссылка с дублированным/кодированным `session` не подменяет сессию; старые проверочные ключи не принимаются; параметры кампании и fragment сохраняются; refresh восстанавливает сессию и черновик; перезапуск создаёт новую сессию; варианты A/B остаются раздельными.

## Правки после сдачи (29.09)

- «Начали» считается по сессиям с активностью помимо `session_started`. Тест: сессия, созданная без дальнейших событий, не попадает в started.
- Откат идёт по журналу активаций. Тест: v1 → v2 → смена долей → откат, откат → v1; повторная публикация не возвращает откаченные версии; старая база без журнала получает его на старте.
- 95% доверительный интервал разницы A/B. Тест: 10/20 против 12/20 — интервал включает ноль, те же доли на 2000 сессий — не включает.
- Генератор на чистой базе v1 даёт прежние 120 / 47 / 29.

## Доверие к событиям (01.10)

До исправления на новой сессии с текущим `intro` два события с пустыми свойствами (`result_viewed`, `cta_clicked`) принимались и давали результат и CTR 100% без прохождения воронки. Этот сценарий воспроизведён отдельно и через HTTP.

- HTTP-регрессия отклоняет результат/CTA до достижения result-шага, подмену шага, происхождения, версии и варианта, клиентские переходы и пользовательское событие результата. Валидное событие в той же пачке принимается, повтор становится `duplicate`. Состояние сессии и результат/CTA в аналитике не меняются от атак.
- Контроль проходит воронку через HTTP, отправляет CTA раньше просмотра результата и повторяет пачку: оба валидных события принимаются, CTR остаётся 100%, дубликаты не увеличивают метрики.
- Проверяются неверные, но существующие в конфиге результат и действие; отложенный ранее выданный результат после смены ветки, Back, отката версии и TTL; событие v3; серверные производные и прямые пользовательские события на разрешённом шаге.
- Миграция сохраняет старые записи с `legacy`, исключает их из метрик и фильтрует их количество по кампании. Последующее достижение результата и повтор старого ID не легализуют поддельную запись. Перезапуск сохраняет контексты. Первый Back после обновления сохраняет контекст предыдущего вопроса и выданного результата.
- Генератор проверен на отдельных базах: v1 — 120 сессий, 951 принятое событие и 280 дублей; v2 — 120, 986 и 285; v3 — 120, 993 и 283. Публичная база генератором не заполнялась.

Проверка подтверждает разрешённость событий по серверному состоянию, но не доказывает физический клик или участие человека.
